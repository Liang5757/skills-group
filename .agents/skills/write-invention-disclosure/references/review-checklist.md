# 技术交底书审查清单

## 事实与证据

- [ ] 技术事实可回指源码、文档、图、日志、实验或发明人说明。
- [ ] 已实现、开发中、概念方案和待验证假设已明确区分。
- [ ] 未编造性能数字、参数、实现细节、发明人或相关文档。
- [ ] 个人联系方式和敏感数据只在确有必要时保留。

## 技术闭环

- [ ] 一句话可以概括技术场景、问题、核心特征和效果。
- [ ] 每个技术问题都有对应技术手段和技术效果。
- [ ] 核心必要特征与可选增强特征已经分开。
- [ ] 方案不是纯业务规则、人工流程、界面展示或抽象目标。

## 章节完整度

- [ ] 基本信息和第 1–6 节齐全，缺口已标记待确认。
- [ ] 背景技术包含最接近现有方案的步骤或结构及因果缺陷。
- [ ] 具体实现包含架构、职责、步骤、数据/控制流、条件和边界。
- [ ] 软件或算法方案至少有方法实施例和系统实施例。
- [ ] 每幅图都有图号、图名和不依赖图片的文字说明。
- [ ] 技术效果包含因果解释；量化指标包含基线和口径。
- [ ] 替代实现覆盖可能被替换的非关键组件和步骤。
- [ ] 相关文档说明了各自用途。

## 保护范围

- [ ] 保护要点以核心技术特征组合为首，而非结果或功能口号。
- [ ] 未把具体产品名、厂商、协议、库或阈值无意写死。
- [ ] 方法步骤与系统模块能够互相映射。
- [ ] 发明名称未机械堆叠正文缺少支持的装置、设备或介质主题。
- [ ] 已考虑步骤省略、增加、合并、并行、换序和等价组件。
- [ ] 未把未经检索的判断写成新颖性、创造性或可授权结论。

## 表达质量

- [ ] 同一对象只有一个稳定名称，主体和指代清晰。
- [ ] 英文术语首次出现时含中文名、英文全称和简称。
- [ ] 编号连续，图号、步骤号和模块名能在正文互相引用。
- [ ] 删除了模板提示、样例残留、重复段落和空泛形容词。
- [ ] 不看附图也能理解完整技术方案。

## 交付附录

- [ ] 待确认事项只保留影响准确性或保护范围的问题。
- [ ] 缺失的证据、实验和附图已列成后续动作。
- [ ] 对事实不足、范围过窄或效果无证据处给出风险提示。
